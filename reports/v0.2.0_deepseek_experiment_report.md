# v0.2.0 DeepSeek 睡眠实验报告

## 简单问答

Wake/Sleep 二分类实验的目标是利用生理信号自动判断每个数据片段属于清醒（Wake）还是睡眠（Sleep），从而实现对睡眠与觉醒状态的识别。

## DeepSeek 数据分析

## 一、数据概况解读

- **规模**：31 名受试者，共 25,199 个 30 秒窗口。总时长约  
  \(25199 \times 30 / 3600 \approx 209.99\) 小时，平均每名受试者约  
  \(25199 / 31 \approx 812.9\) 个窗口，即约 6.77 小时。
- **采样与窗口**：50 Hz、30 秒/epoch，因此每个窗口理论样本数为  
  \(50 \times 30 = 1500\)。`sample_count` 若恒为 1500，则无判别信息。
- **标签分布**：wake 2,180，sleep 23,019；wake 占 8.65%，sleep 占 91.35%，正负比约 **1 : 10.56**。这是一个明显不平衡的二分类问题。
- **受试者分布**：Top 10 受试者窗口数约 955–980，合计 9,617，占总窗口约 38.2%；平均约 961.7 窗口，约 8.01 小时。其余 21 名受试者平均约 742 窗口，约 6.18 小时。受试者间记录长度有一定差异，但不算极端。
- **时间范围**：`epoch_start` 最大值 29,640 秒，约 8.23 小时。注意：若 30 秒无重叠，29,640 秒对应约 989 个窗口，但 top 受试者最大窗口数为 980，说明可能存在非严格 30 秒步长、缺失窗口、重叠窗口或时间戳定义差异，需要核对。
- **特征**：29 个特征全部是 x/y/z/magnitude 的基础统计量：mean、std、min、max、median、rms、energy。缺少频域、时频、时序上下文、体位角、活动计数等特征。

## 二、主要风险

1. **严重类别不平衡**
   - 全预测为 sleep 的准确率就是 91.35%，但 wake 召回为 0。若目标是检测 wake，accuracy 会严重误导。
   - wake 只有 2,180 个窗口，且连续窗口高度相关，真实独立的 wake 事件数可能远小于 2,180。
   - 应重点关注 wake 的召回率、精确率、AUPRC、balanced accuracy、macro F1、MCC。

2. **受试者/时间泄漏风险**
   - 同一受试者的相邻 30 秒窗口高度自相关。若随机按窗口划分训练/验证/测试，同一受试者、相邻时段会同时出现在训练和测试中，导致性能虚高。
   - 必须按 `subject_id` 分组划分，例如 LOSO 或 StratifiedGroupKFold。若做同一受试者内时间预测，则需按时间块划分。

3. **受试者异质性与样本量不均衡**
   - 31 名受试者，个体差异大，佩戴方式、活动水平、睡眠习惯都会影响加速度统计。
   - 记录长度不同，长记录受试者可能主导训练损失。应按受试者加权或报告每受试者指标。

4. **特征冗余与信息不足**
   - `energy` 通常与 `rms² × sample_count` 高度相关；`rms` 与 `energy` 冗余；`mean` 与 `median` 接近；`magnitude` 由 x/y/z 派生，可能共线。
   - 仅有基础统计量，很难区分“安静清醒”和“睡眠”。缺乏频域、时序上下文、体位变化、心率/呼吸等生理信息。
   - `sample_count` 若恒为 1500，应直接删除。

5. **标签与数据质量风险**
   - 需确认 wake/sleep 标签来源：PSG、活动记录、自报还是算法生成？30 秒 epoch 边界是否可靠？
   - 短暂觉醒、入睡后清醒、伪迹、未佩戴段可能污染标签。
   - `epoch_start` 最大值与最大窗口数不完全一致，需检查窗口是否重叠、时间戳是否连续、是否存在缺失或重复。

6. **评估与部署风险**
   - 固定阈值在不同受试者间可能不适用，需在验证集上调阈值并做概率校准。
   - 若逐窗口独立分类，输出会碎片化，不符合睡眠/清醒的时序连续性。

## 三、下一步建议

### 1. 先做数据审计，再建模
- 按受试者统计：窗口数、总时长、wake/sleep 比例、wake 段数、平均段长、最长段。
- 检查 `sample_count` 分布，是否恒为 1500；检查时间戳步长、重叠、缺失、重复。
- 检查特征分布、异常值、常数特征、高度相关特征。
- 输出每受试者标签分布，确认是否存在某些受试者几乎没有 wake，导致交叉验证折间不稳定。

### 2. 建立严格的验证协议
- 首选 **Leave-One-Subject-Out** 或 **StratifiedGroupKFold**，按 `subject_id` 分组。
- 若目标是对新受试者泛化，测试集必须是未见过的受试者。
- 若目标是对同一受试者新时段预测，则按时间前向划分，避免未来信息泄漏。
- 报告每受试者指标，而不仅是全局汇总；用受试者级 bootstrap 估计置信区间。

### 3. 不平衡处理与评估指标
- 训练折内使用 `class_weight='balanced'`、focal loss、加权采样或重采样；不要对验证/测试集重采样。
- 主指标建议：wake 的 PR-AUC、召回率、精确率、F1；整体 balanced accuracy、macro F1、MCC、Cohen’s kappa。
- 同时报告混淆矩阵和阈值调优结果。AUPRC 的随机基线约为 wake 比例 0.0865。

### 4. 特征工程与预处理
- 删除常数特征，例如可能恒定的 `sample_count`。
- 处理 `rms`/`energy`/`mean`/`median` 的冗余，可用相关性、VIF、树模型重要性筛选。
- 按受试者或训练集统计做标准化，保留原始尺度和标准化版本供模型选择。
- 增加频域特征：FFT 功率、频带能量、谱熵、过零率。
- 增加时序上下文：前后 epoch 的均值/方差/差分、滑动窗口统计。
- 若可获取原始信号，可加入一维 CNN、LSTM/GRU、Transformer 或时序卷积模型。

### 5. 建模与后处理
- 基线：逻辑回归、随机森林、LightGBM/XGBoost。
- 若使用逐窗口分类，建议后处理：中值滤波、最小持续时间约束、HMM/CRF、概率平滑。
- 若保留原始信号，可尝试端到端时序模型，减少手工特征信息损失。

### 6. 明确目标定义
- 确认 wake 的定义：是否包含所有清醒、短暂觉醒、入睡后清醒？是否应合并为多类睡眠分期？
- 若临床关注觉醒检测，可能需要单独定义觉醒标签，而不是简单二分类。
- 如果条件允许，补充 PSG、心率、呼吸、体位等信号，以提高 wake/sleep 可分性。

总体判断：数据量在窗口级别看似充足，但受试者仅 31 人、类别严重不平衡、窗口高度相关。当前最优先事项不是直接调模型，而是**建立按受试者分组的验证协议、做数据质量与标签审计、使用适合不平衡数据的评估指标**。否则很容易得到“高准确率但无 wake 检测能力”的虚假结果。

## DeepSeek 实验建议

结论：当前模型被多数类 **Sleep** 主导。准确率 88.67% 低于“全预测 Sleep”的基线 **90.38%**，因此 **accuracy 不可作为主指标**。真正问题是 Wake 类几乎没学好：Wake recall 29.0%，399/562 个 Wake 被误判为 Sleep；同时 263 个 Sleep 被误判为 Wake，导致 Wake precision 只有 38.3%。类别比例约 **1:9.4**，需要优先处理不平衡、阈值和评估协议。

## 下一轮实验建议（按优先级）

### 1. 先修正评估协议与阈值选择
- 使用 **StratifiedGroupKFold**，按受试者/记录分组，避免同一受试者样本泄漏到训练和验证。重复 3–5 次报告均值±标准差。
- 主指标改为：**macro F1、balanced accuracy、Wake F1/recall、Sleep recall、AUPRC（Wake 为正类）、MCC**。当前 balanced accuracy≈0.620，MCC≈0.27，说明整体区分能力弱。
- 必须输出概率并做阈值搜索。默认 0.5 对不平衡数据通常不是最优。建议：
  - 目标 A：最大化 macro F1；
  - 目标 B：约束 Sleep recall ≥ 0.95 下最大化 Wake F1；
  - 目标 C：若 Wake 漏检代价高，优先最大化 Wake recall。
- 阈值只能在验证集上选，测试集只评估一次。

### 2. 低成本高收益：类别不平衡与损失函数
- 若正类设为 Wake，设置 `scale_pos_weight≈5279/562≈9.4`，或 `class_weight='balanced'`。
- 训练折内重采样，验证/测试绝不重采样：
  - Sleep 欠采样到 Wake 的 2–4 倍；
  - 或 Wake 过采样 / SMOTE / ADASYN；
  - 先试“欠采样 + class weight”组合。
- 尝试 **focal loss** 或加权交叉熵，给 Wake 更高权重，例如 alpha≈0.75–0.85，gamma=1–2。
- 模型建议先用 LightGBM / XGBoost + 类别权重 + 概率校准，通常比直接调复杂模型更稳。

### 3. 特征改进：重点补 Wake/觉醒相关特征
当前 Wake 特征可能不足。建议构建 V2 特征集：
- 频域：各频带绝对/相对功率，尤其 alpha、beta、gamma、sigma；alpha/beta 比值。
- 非线性：谱熵、样本熵、排列熵、Hjorth mobility/complexity。
- 生理/行为：EMG、EOG、HRV、心率、呼吸、活动计数、体温。
- 上下文：时间、光照、前一/后一窗口状态、受试者历史、睡眠阶段转换。
- 个体归一化：按受试者做 z-score 或基线校正，减少个体差异。
- 窗口：尝试 30s、60s、5min 多尺度，重叠 50–75%；做消融实验确认增益。

### 4. 模型与后处理
- 使用 **HMM / CRF / BiLSTM / Transformer** 或 LightGBM + HMM 平滑，利用时间连续性减少孤立 Wake/Sleep 切换。
- 可尝试两阶段：第一阶段高召回 Wake 检测，第二阶段对误报 Wake 的 Sleep 样本精炼。
- 若误分类集中在少数受试者，考虑个体校准 / 域适应 / 混合效应模型。
- 对概率做 Platt/isotonic 校准后再调阈值。

### 5. 误差分析必须做
- 分析 399 个 Wake→Sleep 和 263 个 Sleep→Wake 的分布：按受试者、时间段、信号质量、睡眠-觉醒转换期、标签边界。
- 检查 Wake 标签是否含大量伪影或边界模糊样本。
- 若 Wake 样本仅 562 个，考虑额外采集 Wake 数据，或使用迁移学习/预训练。

## 推荐实验顺序
1. 现有特征 + class_weight + 阈值搜索。
2. 训练折内重采样 / focal loss + 阈值搜索。
3. V2 特征集 + 最佳不平衡策略。
4. 序列后处理 / HMM 平滑 + 个体归一化。
5. 概率校准与集成。

## 成功标准建议
下一轮至少达到：  
- macro F1 ≥ 0.70–0.75  
- Wake recall ≥ 0.60–0.70  
- Sleep recall ≥ 0.90–0.95  
- balanced accuracy ≥ 0.80  
- MCC ≥ 0.40  
且按受试者分组 CV 下稳定。若 Wake 漏检代价高，应先牺牲部分 Sleep recall 提升 Wake recall，而不是继续追求 accuracy。

# 实验报告：sleep_automl_agent v0.1.0 baseline

## 实验目的

本项目任务为 `wake_sleep_binary_classification`，目标是在 `sleep_automl_agent` v0.1.0 基线配置下，使用三轴加速度数据、固定 30 秒 epoch，构建 wake/sleep 二分类模型并记录可复现的工程基线。

本实验重点不是证明模型已达到最终性能，而是建立 v0.1.0 基线，暴露数据、标签、验证协议和指标解读问题，为后续不平衡处理、特征扩展和按受试者分组验证提供对照。

## 数据来源

- 项目名称：`sleep_automl_agent`，版本：`v0.1.0`。
- 数据根目录：`data/data`。
- 加速度文件后缀：`_acceleration.txt`。
- 标签文件后缀：`_labeled_sleep.txt`。
- 采样率：`50 Hz`。
- epoch 长度：`30 秒`。
- 加速度列：`['time', 'x', 'y', 'z']`。
- 标签列：`['time', 'stage']`。
- 标签二值映射：
  - wake：`stage in [0]`，映射为 `wake = 0`；
  - sleep：`stage in [1, 2, 3, 5]`，映射为 `sleep = 1`。
- 配置中的 `subject_ids` 为空列表；材料未提供完整受试者 ID 清单，但数据摘要给出 `subject_count = 31`，并给出部分受试者窗口数。
- 数据摘要：
  - 受试者数：31；
  - 窗口数：25,199；
  - 标签分布：wake = 2,180，sleep = 23,019；
  - wake 比例：0.0865；
  - sleep 比例：0.9135；
  - 全量 wake:sleep 比例约 `1:10.56`；
  - 特征数：29；
  - 特征列：`sample_count`, `x_mean`, `x_std`, `x_min`, `x_max`, `x_median`, `x_rms`, `x_energy`, `y_mean`, `y_std`, `y_min`, `y_max`, `y_median`, `y_rms`, `y_energy`, `z_mean`, `z_std`, `z_min`, `z_max`, `z_median`, `z_rms`, `z_energy`, `magnitude_mean`, `magnitude_std`, `magnitude_min`, `magnitude_max`, `magnitude_median`, `magnitude_rms`, `magnitude_energy`；
  - `epoch_start` 范围：`0.0` 到 `29640.0` 秒。
- 数据摘要中 Top 10 受试者窗口数合计 9,617，占全量约 38.2%；平均约 961.7 窗口，约 8.01 小时。其余 21 名受试者平均约 742 窗口，约 6.18 小时。
- 按 25,199 个 30 秒窗口估算，总时长约 `25199 × 30 / 3600 ≈ 209.99` 小时，平均每名受试者约 812.9 窗口，约 6.77 小时。
- 每个 30 秒窗口在 50 Hz 下理论样本数为 `50 × 30 = 1500`；材料未给出 `sample_count` 的实际分布，仅在分析中指出若其恒为 1500，则无判别信息。
- `epoch_start` 最大值 29,640 秒对应约 8.23 小时。若按 30 秒无重叠窗口推算，约对应 989 个窗口，但 Top 受试者最大窗口数为 980，二者存在不一致，需要后续审计时间戳、窗口步长、缺失或重叠定义。

## 方法

- 特征构造：
  - 使用轴：`x`, `y`, `z`, `magnitude`；
  - 启用时域特征：`include_time_domain = True`；
  - 未启用频域特征：`include_frequency_domain = False`；
  - 最终特征数为 29，均为基础时域统计量：`sample_count`，以及 x/y/z/magnitude 的 `mean/std/min/max/median/rms/energy`。
- 标签处理：
  - 将原始睡眠阶段二值化为 wake/sleep；
  - wake 阶段为 `[0]`，sleep 阶段为 `[1, 2, 3, 5]`；
  - 材料未说明 `stage = 4` 的处理方式。
- 训练配置：
  - 模型：`random_forest`；
  - 测试集比例：`test_size = 0.2`；
  - 随机种子：`random_state = 42`；
  - 配置声明：`group_split_by_subject = True`；
  - 输出实验目录：`experiments/v0.1.0_baseline`；
  - 报告路径：`reports/v0.1.0_baseline_report.md`。
- 评估指标：
  - 已提供 `accuracy`、`f1_macro`、`f1_binary_sleep`、`confusion_matrix` 和 `classification_report`；
  - 原始实验指标中未直接提供 AUPRC、AUROC、balanced accuracy、MCC、每受试者指标、置信区间和阈值搜索结果；
  - 本报告中的 balanced accuracy 由分类报告 `macro avg recall` 推导，MCC 由混淆矩阵事后计算或依据输入材料中的分析建议引用。
- 可复现性注意：
  - 数据路径、标签映射、采样率、epoch 长度、特征列表、模型类型、随机种子和输出目录已给出；
  - 但随机森林超参数、训练集/测试集受试者分组明细、概率输出、训练环境、库版本和运行时间未提供；
  - 因此当前记录可支持基线复现框架，但不足以完全复现随机森林内部配置和划分细节。

## 结果

测试集由分类报告 support 推断为 5,841 个窗口，其中 Wake 562 个，Sleep 5,279 个。测试集占全量 25,199 窗口约 23.18%；若测试集为 5,841，则训练集推断为 19,358 个窗口。配置中 `test_size = 0.2`，实际测试集比例偏离 20%，可能与按受试者分组划分有关，但材料未提供分组明细。

|---|---:|
| accuracy | 0.8867 |
| f1_macro | 0.6340 |
| f1_binary_sleep | 0.9381 |
| balanced accuracy，由 macro avg recall 推导 | 0.6201 |
| MCC，由混淆矩阵事后计算约 | 0.27 |

关键结果解读：

- 当前模型 accuracy 为 88.67%，但测试集全预测 Sleep 的多数类基线为 `5279 / 5841 ≈ 0.9038`，即 90.38%。当前模型 accuracy 低于该多数类基线。
- 全量数据 sleep 占比为 91.35%，测试集 sleep 占比为 90.38%；测试集 wake:sleep 约为 `562:5279 ≈ 1:9.39`，全量 wake:sleep 约为 `2180:23019 ≈ 1:10.56`。
- Wake 类表现弱：Wake recall 29.00%，562 个真实 Wake 中有 399 个被误判为 Sleep；Wake precision 38.26%，有 263 个真实 Sleep 被误判为 Wake。

- macro F1 为 0.6340，balanced accuracy 约 0.6201，说明两类平均意义上的区分能力明显弱于 accuracy 所呈现的水平。
- 输入材料中的分析建议指出，当前模型被多数类 Sleep 主导；accuracy 不应作为主指标。

## 讨论

- 类别不平衡是当前结果的核心问题。全量 wake 仅占 8.65%，测试集 wake 仅占 9.62%。Sleep 先验概率极高，模型即使大量漏检 Wake，仍可获得较高 accuracy。
- accuracy 不适合作为主指标。当前 accuracy 88.67% 低于测试集全预测 Sleep 的 90.38%，且 Wake F1 仅 0.3300、Wake recall 仅 29.00%。如果目标是 wake 检测，当前模型不可用。
- Wake 漏检和误报同时存在。399 个真实 Wake 被判为 Sleep，263 个真实 Sleep 被判为 Wake；Wake precision 和 recall 均低，说明默认阈值 0.5 和未处理类别不平衡的随机森林没有形成有效 Wake 判别边界。
- 验证协议需要重点核查。配置声明 `group_split_by_subject = True`，但材料未提供训练/测试受试者列表或分组明细，无法确认是否真正按受试者隔离。若同一受试者相邻窗口同时进入训练和测试，会因窗口高度自相关导致性能虚高；若已按受试者分组，也需要报告每折受试者和每受试者指标。
- 特征信息可能不足。当前 29 个特征全部为 x/y/z/magnitude 的基础时域统计量，频域特征关闭。分析材料指出，这类特征难以区分“安静清醒”和“睡眠”，且 `rms`、`energy`、`mean`、`median`、`magnitude` 之间存在潜在冗余。
- 标签与数据质量风险未解决。材料未说明 wake/sleep 标签来源、30 秒 epoch 边界可靠性、短暂觉醒、入睡后清醒、伪迹和未佩戴段处理；`epoch_start` 最大值与 Top 受试者窗口数不一致，也提示窗口定义可能存在非严格 30 秒步长、缺失、重叠或时间戳差异。
- 逐窗口独立分类可能碎片化。睡眠/清醒具有时间连续性，随机森林逐窗口预测没有利用前后上下文；后续应评估 HMM、CRF、序列模型或中值滤波、最小持续时间约束等后处理。
- 受试者异质性和样本量不均衡需要报告。31 名受试者中，Top 10 受试者占窗口约 38.2%，长记录受试者可能主导训练和全局指标；当前摘要未提供每受试者指标，无法判断误差是否集中在少数受试者。

## 结论

v0.1.0 baseline 的随机森林模型在测试集上得到 accuracy 0.8867、macro F1 0.6340、Sleep F1 0.9381、Wake F1 0.3300。Sleep 类表现较强，但 Wake 类 recall 仅 0.2900，562 个 Wake 中 399 个被误判为 Sleep。测试集全预测 Sleep 的多数类基线为 90.38%，当前 accuracy 低于该基线，因此 accuracy 不能作为该任务的主指标。

当前模型被多数类 Sleep 主导，尚未形成可用的 Wake 检测能力。下一阶段不应直接调参追求 accuracy，而应优先修正评估协议、按受试者分组验证、处理类别不平衡、搜索分类阈值，并扩展与 Wake/觉醒相关的特征。

## 局限性

- 未提供完整受试者 ID 列表和训练/测试分组明细，无法核实 `group_split_by_subject = True` 的实际执行情况。
- 未提供随机森林超参数、训练环境、库版本、训练时间和概率输出，完整复现能力有限。
- 原始指标未包含 AUPRC、AUROC、balanced accuracy、MCC、每受试者指标和置信区间。本报告中的 balanced accuracy 由分类报告推导，MCC 由混淆矩阵事后计算或依据输入分析建议引用。
- 仅有一次划分结果，未提供交叉验证均值、标准差或重复实验，稳定性未知。
- 特征集仅包含时域基础统计量，频域特征关闭；缺少频带功率、谱熵、过零率、时序上下文、体位角、活动计数和生理信号。
- 标签来源和标签质量未说明；`stage = 4` 的处理未说明；伪迹、未佩戴段、短暂觉醒和入睡后清醒是否影响标签未知。
- 数据审计未完成。`sample_count` 是否恒定、时间戳是否连续、窗口是否重叠、`epoch_start` 与窗口数不一致等问题尚未核验。
- 未提供每受试者误差分布，无法判断 Wake 漏检是否集中在少数受试者或特定睡眠-觉醒转换期。
- 当前模型为逐窗口独立分类，未利用睡眠/清醒的时序连续性，预测可能碎片化。

## 后续工作

按优先级建议如下：

1. 数据审计：
   - 按受试者统计窗口数、总时长、wake/sleep 比例、wake 段数、平均段长、最长段；
   - 检查 `sample_count` 分布，确认是否恒为 1500；
   - 检查时间戳步长、重叠、缺失、重复和每受试者覆盖范围；
   - 检查特征分布、异常值、常数特征和高度相关特征；
   - 输出每受试者标签分布，确认是否存在几乎没有 wake 的受试者。

2. 建立严格验证协议：
   - 首选 Leave-One-Subject-Out 或 StratifiedGroupKFold，按 `subject_id` 分组；
   - 若目标是对新受试者泛化，测试集必须包含未见过受试者；
   - 若目标是对同一受试者新时段预测，按时间前向划分，避免未来信息泄漏；
   - 重复 3–5 次并报告均值±标准差；
   - 报告每受试者指标，而不仅是全局汇总。

3. 修正主指标与阈值选择：
   - 主指标改为 macro F1、balanced accuracy、Wake F1/recall、Sleep recall、AUPRC，Wake 为正类，并报告 MCC；
   - 必须输出概率并在验证集上做阈值搜索；
   - 可设定目标：
     - 目标 A：最大化 macro F1；
     - 目标 B：约束 Sleep recall ≥ 0.95 下最大化 Wake F1；
     - 目标 C：若 Wake 漏检代价高，优先最大化 Wake recall；
   - 阈值只能在验证集选择，测试集只评估一次。

4. 处理类别不平衡：
   - 设置 `class_weight = 'balanced'`，或若正类为 Wake，设置 `scale_pos_weight ≈ 5279 / 562 ≈ 9.4`；
   - 训练折内重采样，验证/测试绝不重采样；
   - 可尝试 Sleep 欠采样到 Wake 的 2–4 倍，或 Wake 过采样、SMOTE、ADASYN；
   - 可尝试 focal loss 或加权交叉熵，给 Wake 更高权重。

5. 特征工程 V2：
   - 删除常数特征，例如若 `sample_count` 恒定则删除；
   - 处理 `rms`/`energy`/`mean`/`median` 冗余，用相关性、VIF 或树模型重要性筛选；
   - 按受试者或训练集统计做标准化；
   - 增加频域特征：FFT 功率、频带能量、谱熵、过零率；
   - 增加时序上下文：前后 epoch 的均值/方差/差分、滑动窗口统计；
   - 增加生理/行为信息：EMG、EOG、HRV、心率、呼吸、活动计数、体温等；
   - 尝试 30 秒、60 秒、5 分钟多尺度窗口，并做消融实验。

6. 模型与后处理：
   - 基线可扩展为逻辑回归、随机森林、LightGBM、XGBoost；
   - 对逐窗口分类结果做中值滤波、最小持续时间约束、HMM/CRF、概率平滑；
   - 可尝试两阶段：第一阶段高召回 Wake 检测，第二阶段精炼误报；
   - 对概率做 Platt 或 isotonic 校准后再调阈值；
   - 若误分类集中在少数受试者，考虑个体校准、域适应或混合效应模型。

7. 误差分析：
   - 分析 399 个 Wake→Sleep 和 263 个 Sleep→Wake 的分布；
   - 按受试者、时间段、信号质量、睡眠-觉醒转换期、标签边界分层；
   - 检查 Wake 标签是否包含伪影或边界模糊样本；
   - 若 Wake 样本过少，考虑额外采集 Wake 数据或使用迁移学习/预训练。

8. 推荐实验顺序：
   - 现有特征 + `class_weight` + 阈值搜索；
   - 训练折内重采样或 focal loss + 阈值搜索；
   - V2 特征集 + 最佳不平衡策略；
   - 序列后处理/HMM 平滑 + 个体归一化；
   - 概率校准与集成。

9. 建议成功标准：
   - macro F1 ≥ 0.70–0.75；
   - Wake recall ≥ 0.60–0.70；
   - Sleep recall ≥ 0.90–0.95；
   - balanced accuracy ≥ 0.80；
   - MCC ≥ 0.40；
   - 且按受试者分组 CV 下稳定。
